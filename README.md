# Телемедицина: врач и пациент

- [Установка и запуск на macOS, проверка в двух терминалах](START_HERE.md)
- [Windows: необходимые программы, установка, запуск и сеть](README_WINDOWS.md)

Транскрибацией управляет врач. Пациент автоматически получает очищенный текст
и статус в режиме просмотра, без запуска, остановки и экспорта.

## Документация UDP-сервера

**Новый графический клиент:** запускайте `bash run.sh` из корня проекта.
Сервер, интерфейс и локальная Ollama запускаются вместе; остановка — Ctrl+C
или закрытие окна. Установка, подключение пациента и транскрибация описаны
в [START_HERE.md](START_HERE.md). Ниже сохранена документация консольной версии.

**Анализ головы пациента:** запускайте `.venv/bin/python HeadAnalysisServer.py`
вместо обычного сервера. Обнаружение лица, углы, кивки и повороты отображаются
в окне видеозвонка. Установка и проверка — в [HEAD_ANALYSIS.md](HEAD_ANALYSIS.md).

**Видеозвонки:** после входа в комнату выберите `7` в клиенте. В отдельном окне
доступны своё видео, видео собеседника, кнопки камеры, микрофона и звука.
Установка и запуск описаны в [CLIENT_SETUP.md](CLIENT_SETUP.md).
Клиент с видеозвонками запускайте из окружения с установленными зависимостями:
`.venv/bin/python Client.py` (на Windows `.venv\Scripts\python Client.py`).

Реализация операций с приложенных фотографий на стандартной библиотеке Python.
На фотографиях используется HTTPS; здесь по запросу используется UDP, а `method`,
`path` и числовой `status` являются полями собственного протокола, не HTTP.

Запуск (Python 3):

```sh
python3 Lab_Work_two.py
```

Для подключения с других компьютеров локальной сети:

```sh
python3 Lab_Work_two.py --host 0.0.0.0 --port 5000
```

Клиент указывает IP компьютера с сервером, не `0.0.0.0`.
Сервер хранит комнаты в памяти в течение часа с момента создания.
После перезапуска данные теряются.

## Консольный клиент

В отдельном терминале запустите `python3 Client.py`.
Для другого компьютера: `python3 Client.py --host IP_СЕРВЕРА --port 5000`.

Команды: `1` — создать комнату и войти как врач, `2` — войти как пациент
по коду, `3` — выйти из комнаты, `0` — выйти и закрыть клиент.
Для переписки: `4` — отправить текст, `5` — отправить картинку по пути к файлу,
`6` — проверить входящие сообщения и скачать картинки. Получение выполняется
по команде `6`, автоматического опроса нет. Обмен доступен после входа обоих участников.

Пример: врач и пациент входят в комнату, врач выбирает `4` и пишет сообщение,
пациент выбирает `6` и читает его. Для картинки отправитель выбирает `5` и вводит
полный путь, например `C:\Users\User\Pictures\photo.jpg` на Windows или
`/Users/user/Pictures/photo.jpg` на macOS. Получатель выбирает `6`.
Файл сохраняется в `received_images` относительно папки запуска клиента;
консоль показывает полный путь. Можно задать папку через `--downloads ПУТЬ`.
Картинки автоматически не открываются.

Поддерживаются расширения JPG/JPEG, PNG, GIF, WebP, BMP, HEIC/HEIF, до 5 МБ.
Изображения передаются без преобразования частями по 768 байт с подтверждением
каждой части, повторными запросами при потере ответа и проверкой SHA-256.
Сервер проверяет целостность файла и расширение, но не декодирует изображение.
Если отправка прервалась, повторите `5` с тем же путём: клиент продолжит с
неподтверждённой части. Если прервалось скачивание, повторите `6`.
При тайм-ауте текста повторите `4` с точно тем же текстом.
Данные для продолжения передачи сохраняются только до закрытия клиента.
Лимиты комнаты: 1000 сообщений, 20 картинок и 20 МБ картинок, включая незавершённые.
Текст ограничен 4000 байтами UTF-8. Выход пациента очищает переписку и картинки;
выход врача удаляет комнату. Скачанные файлы остаются у получателя.

После обновления перезапустите сервер и передайте обоим участникам новый `Client.py`.
Для чата достаточно `Client.py`. Для видеозвонков передайте также `VideoCall.py`,
`media.py`, `requirements-client.txt` и инструкцию `CLIENT_SETUP.md`.

Для проверки откройте два клиента: в первом создайте комнату, во втором введите её код.
Выход пациента освобождает место и очищает события прошлого сеанса (курсор `after`
нужно сбросить в 0). Выход врача закрывает комнату. При закрытии через Ctrl+C
клиент также пытается отправить выход. При аварийном завершении это не гарантируется.
После сетевой ошибки сразу повторите ту же команду: клиент сохранит её `id`.
Гарантия подавления повторов ограничена серверным кешем, описанным ниже.

## Сообщения

Одна датаграмма содержит один JSON-объект в UTF-8, не более 60000 байт.
Каждый запрос содержит уникальный строковый `id`, `method`, `path`,
необязательный объект `body` и `token` для защищённых операций.
Ответ содержит тот же `id`, `status` и `body` либо `error`.

| method | path | body | Кто вызывает |
| --- | --- | --- | --- |
| POST | `/rooms` | `{}` | Врач, без токена |
| POST | `/rooms/CODE/join` | `{}` | Пациент, без токена |
| POST | `/rooms/CODE/leave` | `{}` | Оба, с токеном |
| POST | `/rooms/CODE/messages` | `{"text":"Привет"}` | Оба, с токеном |
| GET | `/rooms/CODE/messages?after=0` | `{}` | Оба, с токеном |
| POST | `/rooms/CODE/images` | Часть файла и метаданные | Оба, с токеном |
| GET | `/rooms/CODE/images?id=ID&index=0` | `{}` | Получатель, с токеном |
| POST | `/rooms/CODE/events` | `{"type":"offer","data":{...}}` | Оба, с токеном |
| GET | `/rooms/CODE/events?after=0` | `{}` | Оба, с токеном |
| POST | `/rooms/CODE/frames` | `{"jpeg_base64":"..."}` | Пациент, с токеном |

Создание комнаты возвращает `room`, `token`, `role: doctor` (201).
Подключение возвращает отдельный токен и `role: patient` (200).
Третье место отсутствует. Передача `offer`, `answer`, `ice` возвращает 202.
Чтение возвращает только события собеседника, максимум три за запрос.
Для следующего опроса передавайте полученный `next_after` в `after`.
Полученные события сохраняются, поэтому повторный опрос не теряет их.

JPEG передаётся в Base64, весь запрос должен помещаться в лимит датаграммы.
Для `/frames` большие изображения нужно предварительно уменьшить;
сборка из частей реализована отдельно для картинок чата в `/images`.
Приём ограничен одним кадром в секунду на комнату.
Проверяются только JPEG-маркеры. Функция `analyze(frame)` сейчас возвращает размер
и `analysis: null`: алгоритм анализа на фотографиях не задан.

## Проверка клиентом

Запустите сервер, затем в другом терминале выполните Python-код:

```python
import json
import socket
import uuid

with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as client:
    client.setsockopt(socket.SOL_SOCKET, socket.SO_SNDBUF, 65535)
    client.connect(("127.0.0.1", 5000))
    client.settimeout(2)

    def call(method, path, token=None, body=None):
        request_id = uuid.uuid4().hex
        packet = json.dumps({"id": request_id, "method": method,
                             "path": path, "token": token,
                             "body": body or {}}).encode()
        for _ in range(3):
            client.send(packet)
            while True:
                try:
                    response = json.loads(client.recv(65535))
                except socket.timeout:
                    break
                if response.get("id") != request_id:
                    continue
                if response["status"] >= 400:
                    raise RuntimeError(response)
                return response["body"]
        raise TimeoutError("Сервер не ответил")

    doctor = call("POST", "/rooms")
    path = f'/rooms/{doctor["room"]}'
    patient = call("POST", path + "/join")
    call("POST", path + "/events", doctor["token"],
         {"type": "offer", "data": {"sdp": "пример"}})
    print(call("GET", path + "/events?after=0", patient["token"]))
```

UDP не гарантирует доставку и порядок. При тайм-ауте клиент повторяет **тот же**
пакет с тем же `id` с того же сокета. Сервер запоминает до 1024 успешных ответов
на 120 секунд, чтобы повтор не создавал комнату или событие заново.
После истечения срока или вытеснения ответа защита от повторов не действует.

Это учебный сервер для локальных экспериментов: UDP-сообщения и токены не шифруются.
Браузерный клиент с HTTP API с фотографий с ним несовместим без шлюза.
Аудио/видео WebRTC на исходной схеме идёт между клиентами. Добавленный видеозвонок
реализован собственным UDP-протоколом с пересылкой через сервер; `/events`
остаётся доступным отдельно. Сервер пересылает медиапакеты только участнику той
же комнаты, проверяя токен, адрес медиасокета и состояние камеры/микрофона.
В журнале выводятся изменения состояний устройств и завершение звонка,
без вывода содержимого кадров и звука.
