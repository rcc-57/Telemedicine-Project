# Запуск системы

Для Windows используйте отдельное руководство [README_WINDOWS.md](README_WINDOWS.md).

На Mac нужны Python 3.11, Ollama (https://ollama.com/download/mac), камера/микрофон
и наушники. Для первичной установки нужен интернет. Практический ориентир для врача:
16 ГБ ОЗУ и 12 ГБ свободного места для окружения, моделей и кешей.
Qt, FFmpeg, Docker и Node.js отдельно не требуются. На новом Mac сначала выполните
`bash setup.sh`; после установки обычный запуск не требует загрузки моделей.
Для отдельного компьютера пациента достаточно Python и `requirements-patient.txt`.


## Проверка на одном компьютере из двух терминалов

В первом терминале:

```bash
cd "$HOME/Documents/GitHub/Telemedicine Project"
bash run-doctor.sh
```

Во втором терминале:

```bash
cd "$HOME/Documents/GitHub/Telemedicine Project"
bash run-patient.sh
```

В первом окне нажмите «Я врач • создать». Во втором введите полученный код и
нажмите «Я пациент • войти». Адрес уже настроен на этот компьютер.
Первый запуск поднимает сервер и Ollama, второй открывает только ещё один клиент.
Если система уже запущена через `bash run.sh`, достаточно запустить окно пациента.

Для проверки видео включите камеру только в одном окне — второе получит её видео.
Для проверки речи включите транскрибацию в окне врача, микрофон только в окне
пациента, а воспроизведение звука отключите в обоих окнах, чтобы не было эха.
Произнесите фразу и сделайте паузу: очищенный текст появится у врача.
Чат можно проверить отправкой сообщений в обе стороны.

Ctrl+C во втором терминале закрывает только пациента. Ctrl+C в первом завершает
врача, сервер и Ollama; окно пациента, если оно осталось открытым, закройте отдельно.

## Обычный запуск

В терминале, из папки проекта:

```bash
bash run.sh
```

Открывается приложение «Связь». Одновременно запускаются сервер комнат/видео/анализа головы и отдельная локальная Ollama на порту 11435. Завершение — **Ctrl+C в этом терминале** или закрытие окна. Запуск останавливает только собственные процессы; обычная Ollama на порту 11434 не затрагивается.

1. Врач нажимает «Я врач • создать» и передаёт шестизначный код пациенту.
2. Пациент запускает клиент, вводит IP компьютера врача и код, нажимает «Я пациент • войти».
3. Камера и микрофон изначально выключены. Выберите устройства перед входом и включите кнопками в звонке. На macOS разрешите доступ к устройствам. Используйте наушники.
4. Врач открывает вкладку «Транскрипт» и включает транскрибацию. Обе дорожки распознаются локально, затем обрабатываются Ollama. Готовые фрагменты отображаются с ролями и временем у обоих участников. Пациент видит только текст и статус: кнопок запуска, остановки и экспорта у него нет.
5. «Сохранить очищенный текст» экспортирует только обработанные фрагменты. После завершения звонка они доступны до следующего звонка или закрытия приложения.

## Второй участник

На другом компьютере в той же локальной сети:

```bash
bash run.sh --client-only --host 192.168.1.123
```

Замените адрес на текущий IP компьютера врача. Для проверки двух окон на одном компьютере:

```bash
bash run.sh --client-only
```

Не включайте одну камеру одновременно в двух клиентах. Для пациента достаточно Python-окружения с PySide6, OpenCV, NumPy и sounddevice; модели не нужны. Windows: `.venv\Scripts\python launcher.py --client-only --host IP_СЕРВЕРА`.

## Повторная установка

```bash
bash setup.sh
```

Скрипт создаёт `.venv`, устанавливает библиотеки, скачивает Whisper small и Qwen3 4B. Нужны Python (рекомендуется 3.11), установленная Ollama и интернет для загрузки. Окружение, модели и кеши находятся внутри проекта. `requirements-desktop.lock.txt` фиксирует проверенный набор пакетов на этом Mac; `requirements-desktop.txt` задаёт диапазоны для установки на других системах. FFmpeg отдельно не требуется: декодирование выполняет PyAV.

Дополнительные команды:

```bash
bash run.sh --check          # запуск сервисов, проверка и остановка без окна
bash run.sh --server-only    # сервер + Ollama без интерфейса
bash run.sh --port 5001 --ollama-port 11436
```

При изменении UDP-порта укажите его и второму клиенту. Если порт занят, скрипт выдаст ошибку, не завершая чужие процессы. Журналы сервисов находятся в `runtime/`.

## Как работает обработка речи

ИИ работает на компьютере врача, в отдельном процессе. Обрабатываются микрофон врача и входящая дорожка пациента, независимо от выключения воспроизведения. Фрагменты завершаются на паузах, максимум через 15 секунд непрерывной речи, поэтому это не мгновенные субтитры. Whisper использует русский язык и фильтр речевой активности. Скорость зависит от нагрузки компьютера.

Ollama возвращает найденные подстроки персональных данных; код заменяет их метками. Дополнительно применяются правила для телефонов, почты и номеров документов. Ошибка распознавания/обезличивания скрывает соответствующий фрагмент. При переполнении очереди интерфейс предупреждает о пропуске аудио. Исходные аудио и текст не пишутся на диск. При остановке обработки незавершённые фрагменты удаляются. Чат и присланные изображения не обезличиваются; изображения сохраняются в `received_images/`.

Автоматическое обезличивание может пропустить данные, а распознавание — ошибиться в именах, лекарствах или дозировках. Проверяйте экспорт перед использованием. Это локальный прототип: существующий UDP-транспорт не шифруется, нет эхоподавления и полноценной работы через NAT. Для реальных консультаций через интернет нужен отдельный переход на защищённый транспорт.

## Проверки

```bash
PYTHONPATH=.:Telemedicine_Client .venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/check_desktop.py
```

Вторая команда проверяет настоящие Qt-виджеты, два клиента, чат и завершение комнаты без доступа к камере и микрофону. Снимок интерфейса: `runtime/desktop-preview.png`.

Очищенный транскрипт хранится в памяти сервера комнаты и передаётся пациенту.
При выходе/смене пациента история очищается; врач заново включает обработку для нового сеанса.
Исходное аудио и необезличенный текст на сервер не передаются.
